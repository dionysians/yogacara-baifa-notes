# concept-card

本 Skill 用于在 `大乘百法明门论` 学习项目中自动化维护"概念卡"层——一组轻量、可索引的术语/典籍/人物/比喻/派系卡片，降低初学者的查阅成本。

## 何时触发

**隐式触发（主要）**：每当你准备向 `notes/` 下任何笔记**写入新内容**（Write/Edit 之前）时，先执行本 Skill 扫描即将写入的文本。整合讨论进笔记、创建专题文档、补充章节——全部适用。

**显式触发**：用户输入 `/concept-card <文件路径>` 时，对目标笔记做一次回溯扫描。

## 核心流程

### 1. 识别候选概念

在目标文本中扫描以下类型的概念：

| 类型 | 示例 |
|------|------|
| 典籍 | 《成唯识论》《瑜伽师地论》《百法明门论》《大智度论》《华严经》 |
| 人物 | 玄奘、窥基、护法、安慧、无著、世亲、陈那、法称 |
| 术语 | 种子、现行、熏习、印持、明记、三性、五位、转识成智 |
| 比喻 | 水清珠喻、指月喻、镜智喻 |
| 派系 | 法相唯识、中观、如来藏、五种姓说 |
| 咒语/偈颂 | 八识规矩颂、心经咒、往生咒 |

**排除**：
- 已在当前笔记上下文充分定义、无需外链的概念
- 百法本身（心法/心所法/色法等 100 个法——它们有自己的 notes/ 笔记体系）
- 现代术语（神经科学、LLM 等）

### 2. 对每个候选：用查询脚本检查卡片是否存在

**不要直接用文件遍历或 glob 判断卡片存在性**——用本 Skill 附带的查询脚本：

```bash
python3 .claude/skills/concept-card/query.py lookup <候选名>
python3 .claude/skills/concept-card/query.py lookup-batch <名1> <名2> ...
python3 .claude/skills/concept-card/query.py list
```

返回 JSON。`match` 字段的取值：

| match | 含义 | 处理 |
|-------|------|------|
| `exact` | 候选名正好等于某张卡的 `name` | 按 3a（已存在）处理，用返回的 `path` 加链接 |
| `alias` | 候选名命中某张卡的 `aliases` | 按 3a 处理，链接指向 `path`；**不要**因为名字不同就新建一张卡 |
| `none` | 无匹配 | 按 3b（新建）处理 |
| `conflict` | 候选名同时命中多张卡，或既是一张卡的 name 又是另一张的 alias | 必须由模型判断：根据上下文选择正确的规范卡，若需要则编辑 frontmatter 修正别名归属 |

命名规则（新建卡片时）：直接用概念中文原名，保留书名号。例如：
- `resources/cards/《成唯识论》.md`
- `resources/cards/窥基.md`
- `resources/cards/水清珠喻.md`

**语义近似的判断仍由模型承担**。脚本只做字面 + 别名匹配。如果你怀疑两个字面不同的候选其实是同一概念（如"窥基" vs "慈恩大师"），应该 `lookup` 两次，然后：
- 若其中一个已是规范名 → 把另一个追加进该卡的 `aliases`
- 若都未建 → 只建一张，把另一个名字写进 `aliases`

### 3. 处理分支

**3a. 卡片已存在** → 在目标笔记中，把该概念的**首次出现**替换为 Markdown 链接（相对路径）：

```markdown
[窥基](../../resources/cards/窥基.md)大师说……
```

**仅链接首次出现**，同一笔记内后续重复不再加链（避免视觉污染）。

**3b. 卡片不存在** → 创建新卡片 + 在目标笔记中加链接。

### 4. 卡片格式

**固定元数据 + 自由正文**（维基百科风格）。

#### 固定元数据（必须）

```markdown
---
name: {概念名}
type: 典籍 | 人物 | 术语 | 比喻 | 派系 | 咒语 | 偈颂
aliases: [别号1, 别号2]
---
```

注意：
- **不要加 created 字段**。这些概念都是古远的，创建时间无意义。
- `aliases` 列出该概念的常见异名（如窥基卡的 `aliases: [慈恩大师, 基师, 大乘基]`）。无别名时写 `aliases: []`。后续遇到新别名时，**直接编辑该字段追加**，不要新建卡。

#### 正文结构（灵活，参考维基百科）

开篇必须（仅此两点是硬性要求）：
1. **一级标题 = 概念名**（可含朝代/别号/梵文等基础信息）
2. **开篇段**：一两句话点出概念名 + 核心定义 + 基础说明（让读者在不读下去的情况下也能理解 50%）

开篇之后自由发挥，可按需加章节。常见章节（不是模板，是参考）：

- 人物卡：生平/师承/主要著作/唯识学贡献/与本项目相关的引用
- 典籍卡：作者/成书/结构/核心教义/在本项目中的引用脉络
- 术语卡：词源/定义/在不同宗派中的用法/与相关术语的辨异
- 比喻卡：典故来源/本义/所喻对象/在唯识中的应用
- 派系卡：历史/代表人物/核心主张/与其他派系的争议

**不要用固定模板硬凑章节。** 如果某张卡片天然只需要 3 段话，就只写 3 段；如果某个概念需要展开 10 个章节，就展开 10 个章节。参考维基百科词条的节奏——短概念条目短，重要概念条目长。

### 5. 报告

扫描完成后，在回复中给出简短报告：

```
📇 concept-card 扫描结果
- 新建：《成唯识论》、窥基、水清珠喻
- 引用既有：护法
- 未建（已覆盖或不需要卡片化）：（可选列出）
```

## 重要约束

1. **链接范围**：
   - `notes/` 下的笔记：所有卡片可被链接引用
   - `resources/cards/` 内部：**仅 `type: 术语` 的卡片允许内部互链**（术语之间天然高度交织，不链则查阅成本过高）
   - 人物卡、典籍卡、比喻卡、派系卡、咒语/偈颂卡——**不**在卡内部加指向其他卡的链接（这几类卡互相引用需求低，避免维护负担）
   - 链接仍遵守"首次出现加链"规则
   - 卡片不因被其他卡片引用而产生反向索引，索引方向单向
2. **链接使用相对路径**。`notes/03-心所法/善心所/信.md` 引用卡时写成 `../../../resources/cards/窥基.md`。
3. **卡片创建时的定义来源**：优先使用**当前对话中已讨论过的定义**（最贴合本项目语境），其次使用经典原义。不要瞎编。如果卡片内容把握不足，可以写得短一些，但不要写错。
4. **遵守项目的学术诚实三层原则**（CLAUDE.md 中定义）：
   - 经典原义标经典依据
   - 本项目学习者的自主推论标为第三层
5. **讨论完成并经用户确认后，才更新笔记**（CLAUDE.md 规则）——本 Skill 在模型整合笔记时触发，此时"用户已确认"的前提已成立。
6. **一次整合中批量处理**：单次整合任务中扫描一次、一次性新建多张卡片 + 一次性替换链接；不要每遇到一个概念就打断主流程。

## 别名管理

- 发现已有卡的新别名 → 直接编辑该卡 `aliases` 字段追加
- 无需在回复中事先请求用户批准（低风险、可人工回溯修正）
- 冲突（`match: conflict`）例外：必须在回复中说明并让用户仲裁后再写入

## 命名边界情况

- **书名号**：保留。《成唯识论》写成 `《成唯识论》.md`，而不是 `成唯识论.md`
- **别号/尊号**：以最常用形式为主名，别号在卡片开篇说明。例如用"窥基"而非"慈恩大师"
- **同名不同义**：罕见。如出现，用 `概念名-限定词.md` 区分（如 `信-善心所.md` vs `信-一般用法.md`）——但心所"信"本身是百法之一，不应该做概念卡，而应该用其在 notes/ 下的正规笔记

## 显式调用（/concept-card <path>）

用户显式调用时：
1. 读取目标文件
2. 执行同样的扫描流程
3. 产出新建/链接报告
4. 不要修改卡片目录之外的任何其他笔记
